# Documentation and content rules

1. Write repository documentation and public framing in English only.
2. `bitty-docs` owns canonical product, architecture, security, interface, and
   governance content. This repository owns presentation, not duplicate specs.
3. Consume canonical content from a pinned revision and validate metadata,
   publication eligibility, language, links, and content identity before use.
4. Do not silently edit imported normative text or remove status qualifiers.
5. Keep routes deterministic. A content move records old identity, new identity,
   replacement guidance, and redirect requirements in coordinated changes.
6. Public behavior, content schema, route, redirect, and compatibility changes
   update affected `bitty-docs` contracts before task closure.
7. README and AGENTS guidance must remain portable; do not add links to local or
   machine-specific filesystem paths.
8. Never claim that a planned website, integration, build, deployment, or
   publication exists without current evidence.
