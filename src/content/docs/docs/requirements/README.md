# Requirements

No standalone requirement documents have been accepted yet. This directory will
hold testable outcomes and constraints that future specifications and
implementations must satisfy.

## Admission criteria

A requirement states the actor or system outcome, scope, priority, rationale,
acceptance evidence, and links to product or security authority. It must be
measurable without prescribing an unnecessary implementation mechanism.

## Authority and status

Only reviewed requirements marked `normative` are implementation gates. Draft
requirements are proposals. Architecture and specifications may refine how a
requirement is met but cannot silently weaken a normative security constraint.

## Naming and maintenance

Use `REQ-NNNN-short-title.md` and stable requirement IDs inside the document.
Trace changes to an Issue, CarryCtx decision, affected specifications, tests,
and risks. Supersede rather than reuse identifiers when meaning changes.
